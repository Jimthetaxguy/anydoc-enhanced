# Public test corpus

## Generic document fixtures

`docx/public-fixture.docx` is a synthetic, non-PII WordprocessingML package
used by the MCP integration test. The `ods/` fixture is a public AnyDoc spreadsheet package with two synthetic sheets, typed values, and a merged span. The `xlsx/` fixtures cover one accepted exact
`.xlsx` package and one malformed negative input for the strict Excel route.

Only redistributable, non-identifying fixtures may be committed here. Never
add client documents, personal records, credentials, private filesystem paths,
or a document merely described as "anonymized" without recording its source
and transformation.

## Pinned-AnyDoc hardening corpus

`scripts/build-anydoc-hardening-corpus.py` deterministically generates five
synthetic packages that reproduce AnyDoc 0.2.4 behaviors the local contract
must not inherit: dropped symbol and legacy form checkboxes, hidden runs
converted as ordinary text, external link destinations written into Markdown,
and number-format amplification. The MCP integration tests run each through
the real worker.

## ODP qualification corpus

The odp/ directory contains one MIT-licensed Firecrawl AnyDoc presentation
fixture and deterministic derivatives for identity, completeness, active
content, external references, hidden slides, encryption, malformed XML, and
archive-amplification gates. See odp/README.md for source, transformation, and
hashes. The ODP route is enabled only on Linux hosts where the worker
address-space ceiling is enforceable.

## EPUB qualification corpus

The `epub/` directory contains deterministic synthetic, non-PII packages for
the strict EPUB route and containment evaluator. See [`epub/README.md`](epub/README.md)
for provenance, expected predicates, and SHA-256 values. The public MCP route is
enabled only on Linux where the worker address-space ceiling is enforceable.

## Derived-artifact manifest

These files are generated from the approved source PDFs. The PNGs and scanned
PDFs come from `scripts/build-scanned-corpus.py`; ground truth comes from the
local PDF extraction path; `summary.json` contains OCR measurements for the
three public fixtures only.

The hashes identify the committed artifacts; regeneration is not guaranteed
to be byte-for-byte identical. The current scripts do not pin PIL, Poppler,
ocrs, or OCR model versions, PDF generation may embed timestamps, and elapsed
time is environment-dependent. Treat the summary as a dated, rerunnable
baseline and refresh the manifest whenever artifacts are regenerated.

## Contributor gate

For every new fixture:

1. Record the original public URL or synthetic generator.
2. Record the redistribution basis and SHA-256.
3. Inspect document metadata and embedded attachments.
4. Scan extracted text for names, email addresses, account identifiers, SSNs,
   EINs, credentials, and local paths.
5. Generate derivatives only from the approved source and record the command.

Run the repository secret scan and the Rust test suite before opening a pull
request. A green parser test does not prove a fixture is safe to publish.
